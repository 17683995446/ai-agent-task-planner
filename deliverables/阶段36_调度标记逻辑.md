## 二、核心设计

### 2.1 调度数据结构

```
ScheduledTopology（调度后拓扑）
├── original_topology: TopologyStructure - 原始拓扑
├── scheduled_nodes: List[ScheduledNode] - 调度节点
├── parallel_groups: Dict[str, List[str]] - 并行组
├── serial_batches: List[List[str]] - 串行批次
└── schedule_marks: List[ScheduleMark] - 调度标记

ScheduledNode（调度节点）
├── node_id, name, execution_type - 基本信息
├── group_id, parallel_group - 分组信息
├── dependencies, dependents - 依赖关系
├── priority, can_parallelize - 调度属性

ScheduleMark（调度标记）
├── node_id, name, execution_type
├── group_id, parallel_group
└── batch_order - 批次顺序

ExecutionType（执行类型）
├── SERIAL - 串行
├── PARALLEL - 并行
└── CONDITIONAL - 条件执行
```

### 2.2 组件架构

```
ScheduleMarker（调度标记器）
├── mark_schedule() - 主标记入口
├── _analyze_parallelizability() - 分析可并行性
├── _check_can_parallelize() - 检查是否可并行
├── _get_node_level() - 获取节点层级
├── _group_parallel_nodes() - 分组并行节点
├── _organize_serial_batches() - 组织串行批次
├── _generate_schedule_marks() - 生成调度标记
└── schedule_to_dict() - 转换为字典
```

## 三、核心功能

### 3.1 可并行性分析

**分析策略**：
- 识别同一层级的节点（没有互相依赖关系）
- 同一层级且无交叉依赖的节点可以并行
- 有依赖关系的节点必须串行执行

**判断标准**：
- 节点层级相同
- 不存在互相依赖关系
- 可以同时开始执行

### 3.2 并行节点分组

**分组策略**：
- 按层级分组
- 同一层级的可并行节点分到同一组
- 每个并行组分配唯一的group_id

### 3.3 串行批次组织

**组织策略**：
- 按照拓扑顺序组织批次
- 每个并行组作为一个整体批次
- 有依赖关系的节点分成单独批次
- 确保批次之间的正确依赖顺序

### 3.4 完整调度流程

1. 生成拓扑结构
2. 分析可并行性
3. 分组并行节点
4. 组织串行批次
5. 生成调度标记

## 四、使用示例

### 4.1 基本使用

```python
from topology.schedule_marker import ScheduleMarker, mark_task_schedule, mark_and_get_dict
from topology.subtask_splitter import SubTaskSplitter, SplitStrategy

# 1. 拆分任务
splitter = SubTaskSplitter()
subtasks = splitter.split_task(
    "开发一个Web应用系统",
    task_id="task-webapp",
    strategy=SplitStrategy.BY_PHASE
)

# 2. 标记调度
marker = ScheduleMarker()
scheduled = marker.mark_schedule(subtasks)

# 3. 查看结果
print(f"调度节点数量: {len(scheduled.scheduled_nodes)}")
print(f"并行组数量: {len(scheduled.parallel_groups)}")
print(f"串行批次数量: {len(scheduled.serial_batches)}")

print("\n并行组:")
for group_id, nodes in scheduled.parallel_groups.items():
    print(f"  {group_id}: {nodes}")

print("\n串行批次:")
for i, batch in enumerate(scheduled.serial_batches, 1):
    print(f"  批次 {i}: {batch}")
```

### 4.3 完整流程集成

```python
from topology.subtask_splitter import split_task_into_subtasks
from topology.schedule_marker import mark_and_get_dict

# 完整流程：拆分 → 调度标记
task_desc = "开发一个复杂系统"

# 1. 拆分任务
subtasks = split_task_into_subtasks(task_desc, task_id="task-complex")

# 2. 标记调度
result_dict = mark_and_get_dict(subtasks)

# 3. 使用调度信息
print("执行计划:")
for i, batch in enumerate(result_dict['serial_batches'], 1):
    mark = next((m for m in result_dict['schedule_marks'] if m['node_id'] == batch[0]), None)
    if mark:
        exec_type = mark['execution_type']
    print(f"\n  批次 {i} ({exec_type}):")
    for node_id in batch:
        node_mark = next((m for m in result_dict['schedule_marks'] if m['node_id'] == node_id), None)
        if node_mark:
            print(f"    - {node_mark['name']} ({node_mark['execution_type']})")
```
