# 第23阶段交付物：目标提取与归一化模块

## 一、概述

阶段23完成了唯一Target提取、歧义剔除、目标归一模块的设计和实现。该模块是任务归一建模层的核心组件，负责将复杂的自然语言目标描述转换为标准化的唯一目标结构。

## 二、实现内容

### 2.1 文件位置

```
/src/task_modeling/target_extractor.py
```

### 2.2 核心组件

| 组件 | 类名/函数名 | 职责 |
|-----|-----------|-----|
| 错误异常 | `TargetExtractionError` | 定义目标提取失败时的错误格式 |

| 工厂函数 | `create_extractor()` | 创建提取器实例 |

| 方法名 | 职责 |
|-------|------|
| `extract()` | 主提取方法，实现完整的目标提取流程 |
| `_detect_ambiguity()` | 检测目标描述中的歧义 |
| `_resolve_ambiguity()` | 解决检测到的歧义 |
| `_detect_vague_words()` | 检测模糊词 |
| `_remove_vague_words()` | 移除模糊词 |

| `_extract_measurable_criteria()` | 提取可衡量标准 |

## 三、功能特性

### 3.1 歧义检测与剔除

#### 检测的歧义类型

| 歧义类型 | 关键词 | 处理方式 |
|---------|--------|---------|
| 并列多目标 | "和"、"以及"、"与"、"并且" | 保留第一个目标 |
| 顺序多目标 | "然后" | 保留第一个目标 |

#### 示例

| 输入 | 输出 | 说明 |
|-----|------|-----|
| "生成销售报告和制作PPT" | "生成销售报告" | 检测到"和"，保留第一个目标 |
| "创建文件以及上传服务器" | "创建文件" | 检测到"以及"，保留第一个目标 |

### 3.2 模糊词检测与移除

#### 检测的模糊词类型

| 模糊词类型 | 示例词 | 处理方式 |
|-----------|--------|---------|
| 模糊程度 | "大概"、"可能"、"大约" | 检测并标记 |
| 模糊努力 | "尽量"、"尽力" | 检测并标记 |
| 模糊标准 | "合适"、"适当" | 检测并标记 |
| 模糊质量 | "好一点"、"好些" | 检测并标记 |
| 模糊时间 | "尽快"、"马上" | 检测并标记 |

#### 示例

| 输入 | 输出 | 说明 |
|-----|------|-----|
| "大概生成一个好的销售报告" | "生成一个好的销售报告" | 移除"大概" |
| "尽快完成这个任务" | "完成这个任务" | 移除"尽快" |

### 3.3 目标归一化

#### 归一化规则

| 规则 | 示例 |
|-----|------|
| 统一动词格式 | "生成 报告" → "生成报告" |
| 去除多余空格 | "生成   报告" → "生成报告" |

### 3.4 可衡量标准提取

#### 自动提取的标准类型

| 标准类型 | 提取规则 | 示例输出 |
|---------|---------|---------|
| 页数标准 | 正则匹配"数字+页" | "报告页数>=50页" |
| 数据完整性 | 检测"数据"、"信息"等关键词 | "包含完整必要数据" |
| 图表数量 | 正则匹配"数字+图" | "包含至少10张图表" |
| 默认标准 | 无其他标准时 | "任务完成" |

## 四、使用示例

### 4.1 基本使用

```python
from src.task_modeling.target_extractor import extract_target

# 提取目标
target, records = extract_target('生成2024年度销售报告，50页以上')

print(f'Target ID: {target.id}')
print(f'Description: {target.description}')
print(f'可衡量标准数量: {len(target.measurable_criteria)}')

# 打印处理记录
for record in records:
    print(record)
```

### 4.2 使用提取器实例

```python
from src.task_modeling.target_extractor import TargetExtractor

# 创建提取器
extractor = TargetExtractor()

# 提取目标
try:
    target, records = extractor.extract('生成销售报告和制作PPT')
    print(f'唯一目标: {target.description}')
except TargetExtractionError as e:
    print(f'提取失败: {e.message}')
```

## 六、处理流程

### 6.1 完整处理流程

```
输入：'大概生成销售报告和制作PPT'
  │
  ├─ 步骤1: 歧义检测
  │   └─ 检测到"和" → 记录歧义
  │
  ├─ 步骤2: 歧义解决
  │   └─ 保留"生成销售报告"
  │
  ├─ 步骤3: 模糊词检测
  │   └─ 检测到"大概" → 标记模糊词
  │
  ├─ 步骤4: 模糊词移除
  │   └─ 移除"大概" → "生成销售报告"
  │
  ├─ 步骤5: 归一化处理
  │   └─ 保持"生成销售报告"
  │
  └─ 步骤6: 提取唯一目标
      └─ 输出: "生成销售报告"
```

## 九、技术亮点

### 9.1 设计原则

- **单一职责**：每个方法只负责一个功能
- **可测试性**：每个处理步骤都可独立测试
- **可追溯性**：完整的处理记录便于调试和审计
- **可扩展性**：通过配置化的规则便于扩展新模式

### 9.2 性能考虑

- 正则表达式预编译，提高匹配效率
- 避免不必要的字符串复制
- 一次遍历完成多个检测任务

### 9.3 错误处理

- 统一的异常格式
- 详细的错误信息
- 完整的错误上下文
