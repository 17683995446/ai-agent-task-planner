
# 第4阶段交付物：四层架构职责说明书

---

## 一、整体架构原则（基于公理3）

根据公理3：**复杂系统稳定的唯一条件：分层解耦、单向依赖、原子闭环、分段可校验。**

| 原则 | 说明 | 本系统实现 |
|-----|------|----------|
| 分层解耦 | 每层只解决一个问题，层与层之间完全解耦 | 四层各有唯一职责 |
| 单向依赖 | 上层依赖下层，下层不感知上层 | 建模→拓扑→原子→校验 |
| 原子闭环 | 每个模块独立可验证 | 各层可独立测试 |
| 分段可校验 | 每个阶段完成后可校验结果 | 每层有明确验收标准 |

---

## 二、各层详细职责说明书

### 第一层：任务归一建模层（核心层）

| 属性 | 内容 |
|-----|------|
| **唯一职责** | 将任意用户需求转换为标准四元组结构 |
| **解决痛点** | 目标模糊、无判定标准、任务范围无限、不知道什么时候结束 |
| **边界范围** | 仅负责需求标准化，不负责任务拆解 |
| **输入** | 用户原始自然语言需求 |
| **输出** | 标准四元组 Task（Target/Condition/Boundary/EndRule） |
| **对应根因** | RC-001 目标无定义、RC-002 边界无约束 |
| **验收标准** | 四元组完整、目标明确、边界清晰、终止条件可机器判定 |
| **依赖关系** | 独立最底层，无上层依赖 |

#### 职责详解

1. **Target（目标）归一化**
   - 提取唯一明确目标
   - 移除多歧义表述
   - 转换为可衡量形式

2. **Condition（前置条件）识别**
   - 识别任务启动必要条件
   - 明确条件满足判定标准
   - 标记条件缺失情况

3. **Boundary（边界约束）设定**
   - 任务范围边界
   - 资源约束（时间、算力等）
   - 质量约束标准

4. **EndRule（终止规则）定义**
   - 明确的成功判定条件
   - 机器可自动判定
   - 无模糊表述

---

### 第二层：拓扑依赖拆解层

| 属性 | 内容 |
|-----|------|
| **唯一职责** | 将四元组任务拆解为有向无环图（DAG）结构 |
| **解决痛点** | 步骤无序、依赖混乱、子任务并行串行错乱、关键步骤遗漏 |
| **边界范围** | 仅负责子任务拆分和依赖关系计算，不负责原子化 |
| **输入** | 标准四元组 Task |
| **输出** | DAG 有向无环图（包含子任务节点、依赖边、串行/并行标记） |
| **对应根因** | RC-003 依赖无校验 |
| **验收标准** | 无循环依赖、无悬空节点、无孤立节点、依赖关系正确 |
| **依赖关系** | 仅依赖第一层任务归一建模层 |

#### 职责详解

1. **子任务智能拆分**
   - 基于目标自动拆解合理子任务
   - 确保所有子任务直接服务于最终目标
   - 过滤无关子任务

2. **依赖关系自动计算**
   - 分析子任务之间输入输出关系
   - 识别串行依赖节点
   - 标记并行独立节点

3. **DAG 结构生成**
   - 构建合法有向无环图
   - 自动检测循环依赖
   - 自动检测悬空/孤立节点

4. **调度关系标记**
   - 明确每个节点的前置依赖
   - 标记可并行执行的节点组
   - 确定执行顺序拓扑排序

---

### 第三层：原子动作收敛层

| 属性 | 内容 |
|-----|------|
| **唯一职责** | 将所有子任务收敛为原子动作队列 |
| **解决痛点** | 拆解粒度太粗、一个步骤包含多个行为、机器无法稳定执行 |
| **边界范围** | 仅负责原子化，不负责执行和校验 |
| **输入** | DAG 有向无环图 |
| **输出** | 原子动作队列（每个动作满足三判定标准） |
| **对应根因** | RC-001 目标无定义、RC-004 过程无收敛 |
| **验收标准** | 所有动作原子化、无复合动作、无模糊动作 |
| **依赖关系** | 仅依赖第二层拓扑依赖拆解层 |

#### 职责详解

1. **复合动作自动拆分**
   - 识别包含多个动作的复合步骤
   - 拆分为独立原子动作
   - 保持原有依赖关系

2. **原子动作三标准校验**
   - **单一职责**：一个动作只产生一个确定性结果
   - **无内部流程**：不可继续拆分
   - **可直接执行**：无需二次理解、二次决策

3. **模糊动作净化**
   - 识别抽象层次过高的动作
   - 细化为具体可执行动作
   - 展开条件分支为明确步骤

4. **动作队列生成**
   - 按拓扑顺序组织原子动作
   - 保持依赖关系传递
   - 确保队列可稳定执行

---

### 第四层：分段校验收敛层

| 属性 | 内容 |
|-----|------|
| **唯一职责** | 两段式校验+熔断回滚，确保全程收敛 |
| **解决痛点** | 执行中途偏离目标、无限加步骤、结果不收敛、错而继续执行 |
| **边界范围** | 仅负责校验和收敛，不负责任务生成 |
| **输入** | 原子动作队列 |
| **输出** | 最终收敛结果+执行日志 |
| **对应根因** | RC-004 过程无收敛 |
| **验收标准** | 全程对齐目标、异常自动熔断、结果可收敛、可回滚重规划 |
| **依赖关系** | 仅依赖第三层原子动作收敛层 |

#### 职责详解

1. **子任务级预校验**
   - 执行前检查依赖是否齐全
   - 验证目标是否匹配
   - 确认边界是否超规
   - 不通过则拒绝执行，返回重新拆解

2. **原子动作执行后校验**
   - 每个动作完成后检查输出
   - 验证是否符合下级输入标准
   - 不通过则熔断回滚

3. **熔断回滚机制**
   - 异常自动触发熔断
   - 支持局部回滚
   - 支持局部重规划
   - 避免全局重启

4. **全程收敛监控**
   - 持续对齐初始四元组
   - 检测目标偏移
   - 检测范围越界
   - 任何偏离立即终止迭代

## 三、层间关系说明

### 单向依赖链

```
用户需求
    ↓
[第一层] 任务归一建模层 ← 无依赖
    ↓ 输出：四元组 Task
[第二层] 拓扑依赖拆解层 ← 仅依赖第一层
    ↓ 输出：DAG 图
[第三层] 原子动作收敛层 ← 仅依赖第二层
    ↓ 输出：原子队列
[第四层] 分段校验收敛层 ← 仅依赖第三层
    ↓ 输出：收敛结果
```

### 层间数据流转

| 流向 | 数据格式 | 校验点 |
|-----|---------|-------|
| 用户→第一层 | 自然语言 | 需求完整性检查 |
| 第一层→第二层 | 四元组 Task | 四元组合法性校验 |
| 第二层→第三层 | DAG 图 | 拓扑结构校验 |
| 第三层→第四层 | 原子队列 | 原子化标准校验 |
| 第四层→用户 | 收敛结果 | 终止规则判定 |

| 分段校验收敛层 | 全程对齐目标、异常自动熔断、结果可收敛、可回滚重规划 | DF-021~DF-025（无法收敛类） |
