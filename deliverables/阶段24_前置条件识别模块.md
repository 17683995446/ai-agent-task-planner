## 一、概述

阶段24完成了前置条件Condition自动识别模块的设计和实现。该模块是任务归一建模层的核心组件之一，负责从任务描述中自动识别并提取前置条件，支持多种条件类型的自动分类和机器可判定规则的生成。

```

```

### 2.2 核心组件

| 组件 | 类名/函数名 | 职责 |
|-----|-----------|-----|
| 错误异常 | `ConditionExtractionError` | 定义前置条件提取失败时的错误格式 |

## 三、功能特性

### 3.1 触发关键词识别

#### 支持的触发关键词

| 关键词组 | 类型 | 优先级 |
|---------|------|--------|
| "需要先"、"需要提前"、"必须先" | 时间前置 | 3 |
| "需要"、"需要的"、"需要有" | 资源前置 | 2 |
| "必须"、"必须满足"、"必须要有" | 强制前置 | 3 |
| "前提"、"前提是"、"前提条件" | 逻辑前置 | 3 |
| "依赖"、"依赖于" | 依赖前置 | 3 |

#### 示例

| 输入 | 识别结果 |
|-----|---------|
| "需要先准备好数据，然后生成报告" | 检测到"需要先"，提取"准备好数据" |
| "必须有完整的财务信息" | 检测到"必须有"，提取"完整的财务信息" |

### 3.2 条件类型自动分类

#### 支持的条件类型

| 类型 | 名称 | 关键词 | 规则模板 |
|-----|------|--------|---------|
| `existence` | 存在性检查 | "文件"、"数据"、"资源"、"内容" | `check_existence('{content}')` |
| `value` | 值检查 | "大于"、"小于"、"等于"、"超过" | `check_value('{content}')` |
| `state` | 状态检查 | "完成"、"准备好"、"就绪"、"可用" | `check_state('{content}')` |

#### 示例

| 输入 | 分类类型 | 生成规则 |
|-----|---------|---------|
| "需要销售数据文件" | `existence` | `check_existence('销售数据文件')` |
| "必须准备好" | `state` | `check_state('准备好')` |

### 3.3 默认条件机制

当任务描述中没有明确的前置条件时，自动创建默认条件：

```python
ConditionItem(
    id="C-XXXXXX",
    description="任务开始执行",
    type="state",
    check_rule="True",
    required=False
)
```

## 四、使用示例

### 4.1 基本使用

```python
from src.task_modeling.condition_extractor import extract_condition

# 提取前置条件
condition, records = extract_condition('需要先准备好2024年的销售数据，然后生成报告')

print(f'条件数量: {len(condition.conditions)}')
print(f'逻辑操作符: {condition.logical_operator}')
for cond in condition.conditions:
    print(f'{cond.id}: {cond.description}')
    print(f'  类型: {cond.type}')
    print(f'  检查规则: {cond.check_rule}')
```

### 4.2 使用提取器实例

```python
from src.task_modeling.condition_extractor import ConditionExtractor

# 创建提取器
extractor = ConditionExtractor()

# 提取前置条件
try:
    condition, records = extractor.extract('需要销售数据，需要财务报表')
    print(f'提取到 {len(condition.conditions)} 个条件')
except ConditionExtractionError as e:
    print(f'提取失败: {e.message}')
```

## 六、处理流程

### 6.1 完整处理流程

```
输入：'需要先准备好2024年的销售数据，然后生成报告'
  │
  ├─ 步骤1: 触发关键词扫描
  │   └─ 检测到"需要先"
  │
  ├─ 步骤2: 模式匹配
  │   └─ 匹配到"需要先(.+?)(?:[,，。]|$)"
  │
  ├─ 步骤3: 内容提取
  │   └─ 提取内容: "准备好2024年的销售数据"
  │
  ├─ 步骤4: 类型分类
  │   └─ 检测关键词"准备好" → 分类为state类型
  │
  ├─ 步骤5: 生成检查规则
  │   └─ check_state('准备好2024年的销售数据')
  │
  └─ 步骤6: 组装Condition
      └─ 返回完整的前置条件对象
```

## 九、技术亮点

### 9.1 设计原则

- **配置化规则**：通过配置化的模式和类型定义，便于扩展
- **可插拔设计**：每个类型有独立的分类器和规则模板
- **容错处理**：无明确条件时自动提供默认条件
- **去重机制**：避免重复条件的重复检测

### 9.2 性能考虑

- 一次扫描完成多个模式匹配
- 避免不必要的字符串操作
- 使用set实现高效去重

### 9.3 扩展性

- 新增触发关键词只需在配置中添加
- 新增条件类型只需添加分类器和规则
- 支持自定义逻辑操作符
