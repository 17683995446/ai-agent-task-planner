## 二、核心设计

### 2.1 架构设计

```
ActionSplitter (动作拆分器)
├── split_composite_action(composite, strategy)    # 主拆分入口
├── _split_by_steps(composite, strategy)          # 按步骤拆分
├── _split_by_description(composite, strategy)    # 按描述拆分
├── _try_pattern_match(description, composite)    # 尝试模式匹配
├── _parse_step_to_action(step, index, id, strategy)  # 解析步骤
├── _infer_action_type(step)                      # 推断动作类型
├── _create_default_action(composite, index)      # 创建默认动作
├── split_with_strategy(composite, strategy)      # 使用指定策略拆分
└── add_custom_pattern(pattern, ...)              # 添加自定义模式

CompositeAction (复合动作)
├── composite_id: str
├── name: str
├── description: str
├── steps: List[str]
├── raw_description: str
└── metadata: Dict

SplitStrategy (拆分策略)
├── SEQUENTIAL         # 顺序拆分
├── PARALLEL           # 并行拆分
├── DEPENDENCY_BASED   # 基于依赖拆分
└── DATA_FLOW          # 基于数据流拆分

SplitPattern (拆分模式)
├── pattern: str
├── strategy: SplitStrategy
├── action_type: AtomicActionType
├── name_template: str
└── description_template: str
```

### 2.2 拆分策略详解

#### 1. 顺序拆分 (SEQUENTIAL)
- **适用场景**：有明确步骤的流程
- **行为**：按步骤顺序生成动作，每个动作依赖前一个
- **特点**：简单直接，易于理解

#### 2. 并行拆分 (PARALLEL)
- **适用场景**：无相互依赖的子任务
- **行为**：生成可并行执行的动作
- **特点**：提高执行效率

#### 3. 基于依赖拆分 (DEPENDENCY_BASED)
- **适用场景**：有明确依赖关系的任务
- **行为**：基于依赖关系图拆分
- **特点**：智能识别依赖

#### 4. 基于数据流拆分 (DATA_FLOW)
- **适用场景**：数据处理流水线
- **行为**：按数据流向拆分
- **特点**：优化数据传递

### 2.3 默认拆分模式

```python
内置模式：
- 读取/加载/获取/下载 → DATA_READ
- 写入/保存/存储/上传 → DATA_WRITE
- 处理/转换/解析/计算 → TRANSFORM
- 验证/检查/确认/校验 → VALIDATION
- 调用/请求/API/接口 → API_CALL
- 文件/文档/读写/IO → FILE_IO
```

## 四、使用示例

### 4.1 基本拆分（带明确步骤）

```python
from action_splitter import ActionSplitter, CompositeAction, SplitStrategy

# 创建复合动作
composite = CompositeAction(
    composite_id="data_processing",
    name="数据处理流水线",
    description="从源读取数据、处理、保存",
    steps=[
        "读取原始数据",
        "清洗和转换数据",
        "验证处理结果",
        "保存最终结果"
    ]
)

# 拆分
splitter = ActionSplitter()
queue = splitter.split_composite_action(composite)

# 查看结果
print(f"生成 {len(queue.actions)} 个原子动作")

for action in queue.actions:
    print(f"- {action.name}")
    print(f"  依赖: {action.dependencies}")
```

### 4.2 基于描述的拆分（模式匹配）

```python
# 创建只有描述的复合动作
composite = CompositeAction(
    composite_id="api_workflow",
    name="API调用流程",
    description="读取配置文件、调用API接口、写入结果数据",
    raw_description="读取配置文件、调用API接口、写入结果数据"
)

# 自动匹配模式拆分
queue = splitter.split_composite_action(composite)
# 会自动识别：读取→DATA_READ, 调用→API_CALL, 写入→DATA_WRITE
```

### 4.3 使用不同拆分策略

```python
strategies = [
    (SplitStrategy.SEQUENTIAL, "顺序策略"),
    (SplitStrategy.DEPENDENCY_BASED, "依赖导向"),
    (SplitStrategy.DATA_FLOW, "数据流策略"),
]

for strategy, name in strategies:
    result = splitter.split_with_strategy(composite, strategy)
    print(f"{name}: {result['action_count']} 个动作")
```

### 4.4 添加自定义拆分模式

```python
# 添加自定义模式
splitter.add_custom_pattern(
    pattern=r'发送|推送|通知',
    strategy=SplitStrategy.SEQUENTIAL,
    action_type=AtomicActionType.NETWORK,
    name_template="发送{resource}通知",
    description_template="发送{resource}通知"
)

# 测试自定义模式
composite = CompositeAction(
    composite_id="notification",
    name="通知流程",
    description="发送系统通知、推送更新消息",
    raw_description="发送系统通知、推送更新消息"
)

queue = splitter.split_composite_action(composite)
# 会匹配到自定义的 NETWORK 类型动作
```
