## 一、收敛机制总体架构

根据第四层分段校验收敛层的职责，收敛机制分为两个主要阶段：

```
                        +------------------+
                        |   预校验阶段      |
                        +------------------+
                        | 依赖完整性检查    |
                        | 目标一致性检查    |
                        | 边界约束检查      |
                        +------------------+
                                  |
                                  V
                        +------------------+
                        |  执行阶段         |
                        +------------------+
                        |  执行原子动作1    |
                        |  校验输出1        |
                        |  执行原子动作2    |
                        |  校验输出2        |
                        |  ...              |
                        +------------------+
                                  |
                                  V
                        +------------------+
                        |  终止阶段         |
                        +------------------+
                        |  检查EndRule      |
                        |  (成功/失败)      |
                        +------------------+
```

---

## 二、规则一：子任务级预校验

### 触发条件

在子任务开始执行之前，必须进行预校验。

### 检查内容

| 检查项 | 检查规则 | 说明 |
|-------|---------|------|
| **依赖完整性** | 所有前置依赖都已完成且通过校验 | 确保前置条件满足 |
| **目标一致性** | 当前子任务目标仍与初始四元组目标一致 | 防止任务跑偏 |
| **边界约束检查** | 当前执行未超出时间、资源等边界约束 | 防止无限消耗 |
| **状态有效性** | 当前任务状态为正常可执行状态 | 检查是否已失败或熔断 |

### 校验流程

```python
def pre_validate_subtask(subtask, original_task, execution_history):
    """
    子任务级预校验
    返回：(是否通过, 问题列表)
    """
    issues = []
    
    # 检查依赖完整性
    if not check_dependencies_complete(subtask, execution_history):
        issues.append("前置依赖不完整或未通过校验")
    
    # 检查目标一致性
    if not check_target_consistency(subtask, original_task):
        issues.append("当前子任务目标与原始目标不一致，有跑偏风险")
    
    # 检查边界约束
    if not check_boundary_constraints(execution_history, original_task.boundary):
        issues.append("已超出边界约束（时间、资源等）")
    
    # 检查状态有效性
    if not check_task_state_valid(execution_history):
        issues.append("任务状态异常，不能继续执行")
    
    return len(issues) == 0, issues
```

### 不通过时的决策

| 问题类型 | 处理方式 |
|---------|---------|
| 依赖不完整 | 返回第二层拓扑依赖拆解层，重新计算和补全依赖 |
| 目标不一致 | 返回第一层任务归一建模层，重新确认目标 |
| 边界约束超规 | 终止执行，标记为因边界约束而失败 |
| 状态异常 | 触发熔断机制 |

## 三、规则二：原子动作执行后校验

### 触发条件

每个原子动作执行完成后，必须立即进行校验。

### 检查内容

| 检查项 | 检查规则 | 说明 |
|-------|---------|------|
| **输出完整性** | 动作产生了预期的输出 | 确保输出存在且格式正确 |
| **输出正确性** | 输出内容符合后续动作的输入要求 | 确保数据传递正确 |
| **状态一致性** | 执行后的任务状态与预期一致 | 检查是否产生意外状态 |
| **边界合规性** | 单个动作执行未超出资源限制 | 防止单个动作消耗过多资源 |

### 校验流程

```python
def post_validate_action(action, execution_result, next_actions):
    """
    原子动作执行后校验
    返回：(是否通过, 问题列表)
    """
    issues = []
    
    # 检查输出完整性
    if not check_output_integrity(action, execution_result):
        issues.append("动作未产生预期输出")
    
    # 检查输出正确性（满足后续动作输入要求）
    for next_action in next_actions:
        if not check_output_compatibility(execution_result, next_action):
            issues.append(f"输出不满足后续动作{next_action.id}的输入要求")
    
    # 检查状态一致性
    if not check_state_consistency(execution_result):
        issues.append("执行后状态与预期不一致")
    
    # 检查边界合规性
    if not check_action_boundary(execution_result):
        issues.append("单个动作执行超出资源边界")
    
    return len(issues) == 0, issues
```

### 不通过时的决策

| 问题严重程度 | 处理方式 |
|-----------|---------|
| **严重**（输出完全缺失或错误） | 触发熔断，立即回滚到上一个稳定状态，进行局部重规划 |
| **中等**（输出有小问题但可修复） | 尝试自动修复，修复失败则熔断回滚 |
| **轻微**（不影响后续执行） | 记录警告，继续执行，但增加监控 |

## 四、规则三：熔断触发判定机制

### 熔断阈值体系

| 阈值类型 | 配置项 | 说明 |
|-------|-------|------|
| **连续失败阈值** | max_consecutive_failures | 默认值：3 次连续失败 |
| **总失败次数阈值** | max_total_failures | 默认值：5 次总失败 |
| **单步超时阈值** | step_timeout | 默认值：根据任务类型配置 |
| **整体超时阈值** | total_timeout | 由四元组边界约束定义 |
| **资源消耗阈值** | resource_limit | 由四元组边界约束定义 |
| **目标偏离阈值** | max_drift_score | 默认值：0.3（目标偏离度评分&gt;0.3） |

### 熔断触发条件

熔断条件满足任意一条即触发熔断：

```python
def should_trigger_circuit_breaker(execution_history, task):
    """
    判断是否应该触发熔断
    返回：(是否触发, 触发原因)
    """
    # 1. 连续失败熔断
    if execution_history.consecutive_failures &gt;= task.thresholds.max_consecutive_failures:
        return True, f"连续失败{execution_history.consecutive_failures}次，超过阈值"
    
    # 2. 总失败次数熔断
    if execution_history.total_failures &gt;= task.thresholds.max_total_failures:
        return True, f"总失败{execution_history.total_failures}次，超过阈值"
    
    # 3. 超时熔断
    if execution_history.elapsed_time &gt;= task.boundary.resources.max_time_seconds:
        return True, f"执行时间{execution_history.elapsed_time}s，超过阈值"
    
    # 4. 目标偏离熔断
    drift_score = calculate_target_drift(execution_history, task)
    if drift_score &gt;= task.thresholds.max_drift_score:
        return True, f"目标偏离度{drift_score}，超过阈值"
    
    # 5. 资源消耗熔断
    if check_resource_limit_exceeded(execution_history, task):
        return True, "资源消耗超出阈值"
    
    return False, None
```

### 熔断状态

| 状态 | 说明 |
|-----|------|
| **CLOSED** | 正常状态，正常执行 |
| **OPEN** | 熔断状态，停止执行，等待重置 |
| **HALF-OPEN** | 半开状态，尝试执行少量动作，测试是否恢复 |

## 五、规则四：回滚与局部重规划

### 回滚机制

#### 回滚策略

| 策略 | 说明 | 适用场景 |
|-----|------|---------|
| **单步回滚** | 仅回滚最近一个失败的动作 | 单个动作失败，前后不影响 |
| **节点回滚** | 回滚到当前子任务开始处 | 子任务整体失败，需要重新执行该子任务 |
| **DAG路径回滚** | 回滚到DAG路径中的上一个关键节点 | 路径上多个步骤失败，需要从关键节点重新开始 |
| **全量回滚** | 回滚到任务初始状态 | 严重失败，需要全部重新开始 |

#### 回滚点记录

系统必须在以下位置自动记录回滚点：

1. **每个子任务开始前**
2. **每个关键动作执行后**
3. **每个边界检查前**
4. **用户明确要求的位置**

```python
def create_checkpoint(state, action_history, checkpoint_type):
    """
    创建回滚检查点
    """
    checkpoint = {
        "id": generate_id(),
        "timestamp": get_current_time(),
        "type": checkpoint_type,  # "subtask_start", "key_action", "boundary_check"
        "state": deep_copy(state),
        "history_snapshot": action_history.copy()
    }
    save_checkpoint(checkpoint)
    return checkpoint
```

### 局部重规划

#### 重规划触发条件

| 触发条件 | 重规划范围 |
|---------|---------|
| 单个动作失败 | 仅重规划该动作及后续依赖动作 |
| 子任务失败 | 重规划该子任务及后续子任务 |
| DAG路径错误 | 重规划该路径 |
| 目标轻微偏移 | 重规划相关分支，回归目标 |

#### 重规划流程

```python
def local_replan(task, execution_history, failure_point):
    """
    局部重规划
    返回：(是否成功, 新执行计划)
    """
    # 1. 确定重规划范围
    scope = determine_replan_scope(failure_point)
    
    # 2. 回滚到合适的检查点
    checkpoint = find_nearest_checkpoint(execution_history, scope)
    rollback_to(checkpoint)
    
    # 3. 分析失败原因
    failure_analysis = analyze_failure(failure_point)
    
    # 4. 调整计划
    adjusted_plan = adjust_plan(task, failure_analysis)
    
    # 5. 验证新计划
    if validate_adjusted_plan(adjusted_plan, task):
        return True, adjusted_plan
    else:
        return False, None
```

## 六、收敛状态机

### 状态转换图

```
    [初始化]
        |
        V
    +--------------+
    |  预校验      |-------不通过--->[重新建模/重新拓扑]
    +--------------+
        | 通过
        V
    +--------------+
    |  执行中      |
    +--------------+
        |
        V
    +--------------+
    |  动作后校验  |-------不通过--->[熔断/回滚/重规划]
    +--------------+
        | 通过
        V
    +--------------+
    |  检查终止?   |---是--->[成功/失败终止]
    +--------------+
        | 否
        V
    （回到预校验或执行中，取决于下一步）
```
