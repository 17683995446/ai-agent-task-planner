# 第28阶段交付：无效任务拦截与标准化拒绝反馈

## 一、阶段概述

本阶段完成了基于第一性原理的AI Agent任务规划系统的无效任务拦截与标准化拒绝反馈模块开发。该模块能够对校验失败的任务进行拦截，生成用户友好的标准化错误反馈，并决定是否允许任务进入下游规划流程。

**阶段工作内容**：完善无效任务拦截、标准化拒绝反馈  
**交付物**：异常拦截逻辑  
**验收标准**：非法任务禁止进入下游规划

## 二、异常拦截逻辑设计

### 2.1 核心功能

异常拦截逻辑的主要功能包括：
1. **错误解析**：将校验错误字符串解析为结构化的错误对象
2. **错误分类**：根据错误类型分类（缺少字段、格式错误、逻辑错误等）
3. **拒绝级别判定**：根据错误严重程度判定任务拒绝级别
4. **建议生成**：根据错误类型自动生成修复建议
5. **标准化输出**：生成用户友好的错误消息和结构化JSON响应

### 2.2 模块架构

```
TaskInterceptor（任务拦截器）
├── intercept()：主拦截入口
├── _parse_errors()：解析错误列表
├── _classify_error()：分类错误原因
├── _extract_field()：提取错误字段
├── _determine_severity()：判断错误严重程度
├── _determine_rejection_level()：判定拒绝级别
└── _generate_suggestions()：生成修复建议
```

## 三、拒绝级别体系

### 3.1 拒绝级别定义

| 级别 | 值 | 说明 | 是否允许进入下游 |
|------|-----|------|----------------|
| PASS | pass | 通过，无错误 | ✓ 是 |
| WARNING | warning | 警告，有小问题但可处理 | ✓ 是 |
| REJECTED | rejected | 拒绝，非法任务禁止进入 | ✗ 否 |

### 3.2 拒绝级别判定规则

1. **PASS（通过）**：没有任何校验错误
2. **REJECTED（拒绝）**：满足以下任一条件
   - 关键字段（Target/Condition/Boundary/EndRule）缺失
   - 警告数量超过阈值（5个）
3. **WARNING（警告）**：有错误但非关键字段

### 3.3 错误原因分类

| 原因 | 值 | 说明 |
|------|-----|------|
| MISSING_FIELD | missing_field | 缺少必要字段 |
| INVALID_FORMAT | invalid_format | 格式无效 |
| LOGIC_ERROR | logic_error | 逻辑错误 |
| SEMANTIC_ERROR | semantic_error | 语义错误 |
| RESOURCE_EXCEEDED | resource_exceeded | 超出资源限制 |
| UNKNOWN_ERROR | unknown_error | 未知错误 |

## 五、使用示例

### 5.1 基本使用

```python
from task_modeling.task_interceptor import intercept_task
from task_modeling.task_validator import validate_task

# 创建任务
task = create_your_task()

# 校验任务合法性
is_valid, errors = validate_task(task)

if not is_valid:
    # 拦截并生成标准化反馈
    response = intercept_task(errors, task.id)
    
    # 输出用户友好的错误消息
    print(response.to_user_message())
    
    # 判断是否允许进入下游
    if not response.is_allowed:
        print("任务被拒绝，无法继续！")
```

### 5.2 完整流程集成

```python
from task_modeling.task_validator import validate_task
from task_modeling.task_interceptor import intercept_task

def process_task(task):
    # 1. 校验任务合法性
    is_valid, errors = validate_task(task)
    
    # 2. 如果校验失败，生成拦截响应
    if not is_valid:
        response = intercept_task(errors, task.id)
        
        # 3. 根据拒绝级别决定后续操作
        if response.level == "rejected":
            # 记录日志
            logger.error(f"任务 {task.id} 被拒绝: {response.summary}")
            # 返回错误给用户
            return {"status": "rejected", "message": response.to_user_message()}
        
        # 4. 如果是警告，记录但继续
        elif response.level == "warning":
            logger.warning(f"任务 {task.id} 有警告: {response.summary}")
    
    # 5. 通过校验，进入下游处理
    return {"status": "passed", "task": task}
```
