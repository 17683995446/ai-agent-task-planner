## 一、原子动作三条判定公理

根据第三层原子动作收敛层的职责，原子动作必须满足以下三条硬性判定公理标准：

| 公理编号 | 公理名称 | 公理内容 |
|---------|---------|---------|
| **Axiom-1** | 单一职责 | 一个动作只产生一个确定性结果 |
| **Axiom-2** | 无内部流程 | 不可继续拆分，不可进一步细分为更小的动作 |
| **Axiom-3** | 可直接执行 | 无需二次理解、二次决策，可由执行器直接执行 |

这三条公理必须同时满足，缺一不可。

---

## 二、判定标准详解

### 标准一：单一职责（Single Responsibility）

#### 判定规则

| 规则编号 | 规则名称 | 判定条件 |
|---------|---------|---------|
| **S1-1** | 唯一输出 | 每个动作只有一个明确的输出（文件、数据、状态变化等） |
| **S1-2** | 确定性结果 | 相同的输入必须产生完全相同的输出，没有随机性或不确定性 |
| **S1-3** | 单一目标 | 动作描述中不能包含"和"、"与"等并列关系词汇 |
| **S1-4** | 无副作用隔离 | 除了预期的输出，不产生其他无关的副作用（必要的副作用必须清晰标注） |

#### 验证方法

```python
def check_single_responsibility(action):
    """
    检查动作是否满足单一职责标准
    返回：(是否满足, 问题描述)
    """
    # 检查输出数量
    if len(action.outputs) &gt; 1:
        return False, f"有{len(action.outputs)}个输出，应该只有一个"
    
    # 检查动作描述中是否包含并列连词
    conjunction_words = ['和', '与', '以及', '同时', '并且', '然后']
    for word in conjunction_words:
        if word in action.description:
            return False, f"描述中包含并列词\"{word}\"，可能需要拆分"
    
    # 检查是否有确定性
    if not action.is_deterministic:
        return False, "动作结果不确定，无法保证单一输出"
    
    return True, "满足单一职责标准"
```

#### 合法示例

| 示例编号 | 动作描述 | 是否合法 | 说明 |
|---------|---------|---------|------|
| **S-EX1** | 下载文件 data.csv | ✅ 合法 | 只有一个输出：data.csv 文件 |
| **S-EX2** | 读取数据库表 users | ✅ 合法 | 只有一个输出：users 表数据 |
| **S-EX3** | 将图像转换为 PNG 格式 | ✅ 合法 | 只有一个输出：PNG 图像 |

#### 非法示例

| 示例编号 | 动作描述 | 问题说明 | 建议拆分方案 |
|---------|---------|---------|----------|
| **S-BAD1** | 下载文件 data.csv 并上传到服务器 | ❌ 非法 | 包含"并"，有两个输出 | 拆分1：下载文件 data.csv；拆分2：上传文件到服务器 |
| **S-BAD2** | 读取数据库并分析数据 | ❌ 非法 | 包含"并"，有两个独立动作 | 拆分1：读取数据库表；拆分2：分析数据 |
| **S-BAD3** | 随机生成一个数字 | ❌ 非法 | 结果不确定，违反 S1-2 | 改为：从指定范围生成伪随机数（指定种子） |

### 标准二：无内部流程（No Internal Process）

#### 判定规则

| 规则编号 | 规则名称 | 判定条件 |
|---------|---------|---------|
| **S2-1** | 原子粒度 | 动作描述为单一动词短语，不包含步骤描述 |
| **S2-2** | 无条件分支 | 描述中不能包含"如果"、"则"、"否则"等条件词 |
| **S2-3** | 无循环逻辑 | 描述中不能包含"重复"、"循环"、"遍历"等循环词 |
| **S2-4** | 技术可执行 | 对应一个最小的可执行技术操作（如单个 API 调用、单个系统命令） |

#### 验证方法

```python
def check_no_internal_process(action):
    """
    检查动作是否满足无内部流程标准
    返回：(是否满足, 问题描述)
    """
    # 检查是否包含条件词
    condition_words = ['如果', '若', '假设', '则', '否则', '当']
    for word in condition_words:
        if word in action.description:
            return False, f"描述中包含条件词\"{word}\"，需要展开成多个动作"
    
    # 检查是否包含循环词
    loop_words = ['重复', '循环', '遍历', '迭代', '直到']
    for word in loop_words:
        if word in action.description:
            return False, f"描述中包含循环词\"{word}\"，需要拆分为原子迭代"
    
    # 检查是否是最小技术操作
    if not action.is_technical_primitive:
        return False, "动作不是最小技术操作，需要进一步拆分"
    
    return True, "满足无内部流程标准"
```

#### 合法示例

| 示例编号 | 动作描述 | 是否合法 | 说明 |
|---------|---------|---------|------|
| **P-EX1** | 调用 API GET /api/users | ✅ 合法 | 单一技术操作，无内部流程 |
| **P-EX2** | 执行命令 mkdir temp | ✅ 合法 | 单一系统命令，无内部流程 |
| **P-EX3** | 打开文件 report.txt | ✅ 合法 | 单一文件操作，无内部流程 |

#### 非法示例

| 示例编号 | 动作描述 | 问题说明 | 建议拆分方案 |
|---------|---------|---------|----------|
| **P-BAD1** | 如果文件存在，则删除它 | ❌ 非法 | 包含条件逻辑 | 拆分1：检查文件是否存在；拆分2：删除文件 |
| **P-BAD2** | 遍历所有文件夹并读取文件 | ❌ 非法 | 包含循环逻辑 | 由调度器控制循环，原子动作仅读取单个文件 |
| **P-BAD3** | 处理数据并生成报告 | ❌ 非法 | 包含内部流程 | 进一步拆分为具体原子操作 |

### 标准三：可直接执行（Directly Executable）

#### 判定规则

| 规则编号 | 规则名称 | 判定条件 |
|---------|---------|---------|
| **S3-1** | 无歧义性 | 描述完全清晰，不使用模糊或抽象词汇 |
| **S3-2** | 参数完整 | 执行所需的所有参数都已明确，无需额外询问或推断 |
| **S3-3** | 无需理解 | 执行器不需要理解任务上下文或意图，只需按指令执行 |
| **S3-4** | 无需决策 | 执行过程中不需要做任何选择或判断 |

#### 验证方法

```python
def check_directly_executable(action):
    """
    检查动作是否满足可直接执行标准
    返回：(是否满足, 问题描述)
    """
    # 检查是否包含模糊词
    vague_words = ['适当', '合理', '合适', '尽量', '可能', '大概', '好的']
    for word in vague_words:
        if word in action.description:
            return False, f"描述中包含模糊词\"{word}\"，需要明确化"
    
    # 检查参数完整性
    if not action.has_all_required_params:
        return False, "缺少必要执行参数，无法直接执行"
    
    # 检查是否需要上下文理解
    if action.requires_context_understanding:
        return False, "动作需要理解上下文，不满足直接执行"
    
    # 检查是否需要决策
    if action.requires_decision_making:
        return False, "动作包含决策逻辑，不满足直接执行"
    
    return True, "满足可直接执行标准"
```

#### 合法示例

| 示例编号 | 动作描述 | 是否合法 | 说明 |
|---------|---------|---------|------|
| **E-EX1** | 读取 /data/source.csv 文件 | ✅ 合法 | 描述清晰，参数完整，可直接执行 |
| **E-EX2** | 调用 POST /api/upload 并提交 payload | ✅ 合法 | 描述清晰，无需理解上下文 |
| **E-EX3** | 将值 42 写入变量 count | ✅ 合法 | 描述清晰，无需决策 |

#### 非法示例

| 示例编号 | 动作描述 | 问题说明 | 改进建议 |
|---------|---------|---------|--------|
| **E-BAD1** | 读取数据文件 | ❌ 非法 | 缺少具体文件路径 | 明确：读取 /data/source.csv 文件 |
| **E-BAD2** | 适当调整参数 | ❌ 非法 | 包含模糊词"适当" | 明确：将参数 temperature 调整为 0.7 |
| **E-BAD3** | 查看结果并决定下一步 | ❌ 非法 | 需要决策 | 拆分为：查看结果；执行动作 A；执行动作 B（由调度器决定） |

## 三、综合验证流程

### 验证决策树

```
                    开始验证
                        |
        -----------------------------------
        |         |         |           |
      S1验证    S2验证     S3验证    验证通过
        |         |         |
    通过？    通过？     通过？
        |         |         |
       否        否         否
        |         |         |
    返回问题    返回问题   返回问题
```

### 完整验证函数

```python
def validate_atomic_action(action):
    """
    完整验证一个动作是否满足原子动作三条标准
    返回：(是否合法, 问题列表)
    """
    issues = []
    
    # 检查标准一
    s1_valid, s1_msg = check_single_responsibility(action)
    if not s1_valid:
        issues.append(("单一职责", s1_msg))
    
    # 检查标准二
    s2_valid, s2_msg = check_no_internal_process(action)
    if not s2_valid:
        issues.append(("无内部流程", s2_msg))
    
    # 检查标准三
    s3_valid, s3_msg = check_directly_executable(action)
    if not s3_valid:
        issues.append(("可直接执行", s3_msg))
    
    return len(issues) == 0, issues
```

## 四、原子动作 vs 非原子动作对比表

| 特性 | 原子动作 | 非原子动作（复合动作） |
|-----|---------|------------------|
| **职责数量** | 1 个 | &gt; 1 个 |
| **可拆分性** | 不可 | 可继续拆分 |
| **确定性** | 100% 确定 | 可能不确定 |
| **执行要求** | 无需理解，直接执行 | 需要理解上下文 |
| **参数要求** | 必须完整明确 | 可能模糊，需要推断 |
| **适合直接执行** | ✅ 是 | ❌ 否，需要先拆分 |
