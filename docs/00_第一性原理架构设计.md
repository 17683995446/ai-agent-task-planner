
基于第一性原理的 AI Agent 任务规划系统架构设计文档

0. 设计前置：第一性原理设计准则

0.1 核心设计思想

摒弃市面上「Prompt 优化、多层反思、流程堆砌」的经验式修补方案，剥离所有行业惯性、现成范式、叠加式优化。

回归事物最底层不可推翻的公理，从零推导：

1. 任务执行的本质是什么？
2. Agent 规划出错的根因本质是什么？
3. 满足正确规划需要的最小必要条件是什么？
4. 如何用最简架构覆盖所有问题，无冗余、无装饰、无补丁？

0.2 本系统四大第一性公理（不可违背）

所有架构、模块、逻辑、规则全部由以下 4 条公理推导而来，无任何主观经验设计

公理 1【任务本质公理】：所有人类任务，都是「明确目标 + 有限前置条件 + 固定依赖关系 + 可终止步骤序列」，不存在无限任务、无逻辑任务。
公理 2【Agent 出错根因公理】：所有规划崩坏（跑偏、遗漏、逻辑乱、步骤粗），仅源于四种底层缺陷：目标无定义、边界无约束、依赖无校验、过程无收敛。
公理 3【执行稳定公理】：复杂系统稳定的唯一条件：分层解耦、单向依赖、原子闭环、分段可校验。
公理 4【最简有效公理】：最优架构 = 只保留必要模块，移除所有辅助性、修补性、冗余性逻辑。

0.3 设计目标（纯底层目标，无商业修饰）

1. 彻底解决 Agent 任务拆解粗、步骤遗漏、顺序错乱、目标偏移、无限推演五大核心缺陷
2. 实现任意复杂度任务的可解释、可复现、可收敛、可校验规划
3. 架构极致轻量化，无冗余逻辑，适配所有 LLM、所有 Agent 框架
4. 全流程机器可解析、可自动化、可嵌入工程代码


1. 问题底层溯源（第一性拆解，拒绝表面归因）

1.1 市面 Agent 规划所有问题的唯一底层根因

不是模型不够聪明、不是 Prompt 不够详细、不是反思次数太少。

本质根因：市面所有通用 Agent，缺少「任务结构化数学建模层」

- 模型是概率生成文本，天生不具备逻辑约束、边界约束、依赖约束
- 直接让 LLM 端到端规划 = 用随机概率解决确定性逻辑问题
- 所有后期的反思、重试、校验、复盘，都是事后补丁，无法根治

1.2 问题推导结论

想要根治规划弱，不能优化输出，必须重构输入与约束机制
需要一套「结构化规则层」，约束 LLM 的生成逻辑，而非依赖 LLM 自觉正确。


2. 系统整体架构（第一性最简分层）

2.1 架构设计原则（严格第一性）

1. 分层唯一职责：每层只解决一个底层问题
2. 依赖唯一规则：上层依赖下层，下层不感知上层，单向无环
3. 模块唯一标准：删除该模块则系统必然失效，即为必要模块；可删除则为冗余模块，直接剔除

2.2 四层极简架构（无冗余、无补丁、全覆盖）

从底层到上层，逐层解决一个核心缺陷：

1. 任务归一建模层（解决：目标模糊、无终止条件）
2. 拓扑依赖拆解层（解决：顺序乱、遗漏前置、逻辑颠倒）
3. 原子动作收敛层（解决：步骤过粗、一步多事、不可执行）
4. 分段校验收敛层（解决：中途跑偏、无限推演、执行失效）

架构本质：用结构化数学逻辑锁死流程，LLM 仅作为填充内容的执行单元


3. 各模块详细设计（第一性推导落地）

3.1 第一层：任务归一建模层（最底层核心）

核心解决的底层问题

无明确目标、无判定标准、任务范围无限、不知道什么时候结束

建模四元组（任务的最小完整公理结构）

任何任务，必须被建模为四元组，缺一不可：

第一性推导逻辑

根据公理 1：所有任务必有目标、前置、边界、终止条件。
没有四元组的任务 = 未定义任务，禁止进入规划流程，从源头杜绝瞎拆解。

3.2 第二层：拓扑依赖拆解层

核心解决的底层问题

步骤无序、依赖混乱、子任务并行串行错乱、关键步骤遗漏

核心机制：有向无环拓扑拆分

1. 基于四元组 Task，拆解出一级子任务节点
2. 自动计算节点依赖关系，生成DAG 有向无环图
3. 严格区分：串行依赖节点 / 并行独立节点
4. 禁止出现循环依赖、悬空节点、孤立节点

拆解硬性公理规则

1. 所有子任务必须直接服务于最终 Target，无关任务直接剔除
2. 后序节点必须包含前序节点的输出作为输入
3. 无前置依赖的节点，方可并行执行

3.3 第三层：原子动作收敛层

核心解决的底层问题

拆解粒度太粗、一个步骤包含多个行为、机器无法稳定执行

原子动作第一性定义（不可再分最小单元）

满足以下三个必要充分条件即为原子动作：

1. 单一职责：一个动作只产生一个确定性结果
2. 无内部流程：不可继续拆分
3. 可直接执行：无需二次理解、二次决策

收敛规则

所有子任务，必须向下收敛为原子动作队列
禁止：复合动作、模糊动作、条件不确定动作

3.4 第四层：分段校验收敛层

核心解决的底层问题

执行中途偏离目标、无限加步骤、结果不收敛、错而继续执行

两段式收敛机制（第一性最优解）

1. 子任务级预校验
每一组子任务执行前：校验依赖是否齐全、目标是否匹配、边界是否超规
不通过 → 拒绝执行，重新拆解
2. 原子动作执行后校验
每一个原子动作执行完成：校验输出是否满足下一级输入标准
不通过 → 熔断回滚、重规划，禁止继续推进

终极收敛公理

所有执行过程，必须时刻可收敛到初始 Task 四元组
任何偏离，立即终止迭代。


4. 核心运行全流程（最简闭环、无冗余步骤）

基于四大层，生成唯一标准执行链路，无多余逻辑：

1. 任务归一建模：用户原始需求 → 生成标准四元组 Task
2. 合法性校验：无目标 / 无边界 / 无终止条件 → 直接拒绝规划
3. 拓扑子任务拆解：生成 DAG 依赖任务图，区分串行 / 并行
4. 原子动作下沉：所有子任务拆解为可执行原子队列
5. 预校验拦截：校验整体逻辑闭环、依赖完整
6. 分段迭代执行：按拓扑顺序执行，逐动作校验
7. 收敛判定：满足 EndRule 则终止，不满足则局部重规划

全流程无人工干预、无模糊空间、无事后补丁


5. 根治所有规划缺陷的对应证明（第一性闭环）

市面 Agent 缺陷 底层根因 本系统根治机制 
任务跑偏、越做越偏 无固定目标与边界约束 四元组锁死目标 + 全程对齐校验 
步骤遗漏、逻辑不全 无依赖拓扑校验 DAG 有向无环图强制补齐前置依赖 
拆解太粗、无法落地 无原子定义标准 三层原子收敛，强制最小执行单元 
顺序颠倒、流程混乱 无先后依赖约束 单向拓扑依赖，禁止逆序执行 
无限推演、无法终止 无明确终止规则 机器可判定 EndRule，强制收敛 
失败硬跑、错继续做 无熔断回滚机制 分段校验 + 局部重规划熔断 

结论：本架构从公理层面覆盖所有规划缺陷，无遗漏、无补丁、无侥幸。


6. 工程落地规范（机器可直接对接）

6.1 架构核心特性

1. 模型无关：不依赖特定 LLM，任何模型均可适配
2. 框架无关：可嵌入任意 Agent 框架
3. 全结构化：所有输出为结构化数据，而非自由文本
4. 可观测、可审计、可追溯：每一步规划有据可依

6.2 最简接入伪代码（核心逻辑）


7. 设计总结（第一性终极结论）

1. Agent 规划弱不是模型能力问题，是缺少结构化约束层的底层架构问题
2. 所有市面上的反思、复盘、多轮规划、CoT、ToT，都是表层优化，无法根治
3. 本方案基于四条不可推翻的底层公理推导，无任何经验堆砌
4. 架构极简、分层唯一职责、单向依赖、完全闭环，符合极致工程化标准
5. 可彻底解决：步骤乱、遗漏、跑偏、粗粒度、不收敛、无限推演所有问题
